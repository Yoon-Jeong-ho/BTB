# Curriculum Architect

## Responsibilities

- `00 -> 09` ladder 안에서 track 구조, numbering, prerequisite를 유지한다.
- unit 간 선수지식과 status progression(`planned -> outlined -> runnable`)을 정리한다.
- README 수준의 구조와 상태 표기가 전체 BTB workflow와 일관되게 보이도록 관리한다.

## Inputs

- 확장 디자인 스펙과 phase plan
- 기존 track README, study guide, status manifest
- Program Director의 lane brief와 목표 상태

## Outputs

- track/unit 구조안과 prerequisite 정리
- numbering 및 naming 기준 반영안
- 상태 progression과 문서 계약에 대한 변경 제안

## Done Criteria

- 새 문서/유닛이 기존 ladder와 충돌하지 않는다.
- prerequisite 흐름이 명확하고 이전 track과의 연결이 설명된다.
- 상태 표기와 구조 규칙이 README, guide, manifest와 일치한다.

## Common Failure Modes

- numbering은 맞지만 prerequisite 설명이 비어 있어 흐름이 끊긴다.
- track 역할 경계를 섞어 foundations/ML/deep learning/NLP/system 구분이 흐려진다.
- 상태 모델을 문서마다 다르게 써 독자가 완성도를 오해한다.
